Podemos começar?

Cofre de Código (GitHub)

O GitHub é o "cofre digital" do seu projeto. É lá que cada linha de código fica guardada com segurança e cada mudança é registrada. Sem isso, não tenho como criar repositórios, abrir PRs ou versionar nada automaticamente.

1 No GitHub, clique na sua foto de perfil (canto superior direito) → Settings.
2 No menu lateral, desça até o final → Developer settings → Personal access tokens → Tokens (classic).
3 Clique em Generate new token (classic), marque a caixinha repo e clique em gerar. Copie o token antes de fechar!

O Cérebro (Supabase)

O Supabase é onde os dados de todos os seus projetos vão morar — o banco, as regras de acesso, os arquivos. Com a chave global, consigo criar e gerenciar projetos inteiros sem precisar te pedir permissão toda hora.

1 Acesse supabase.com → faça login → clique na sua foto no canto superior direito.
2 Vá em Account → Access Tokens → clique em Generate new token.
3 Dê um nome (ex: shark-method) e copie o token gerado. Ele começa com sbp_.

A Vitrine (Vercel)

A Vercel é o "letreiro iluminado" do seu produto — é onde o site fica disponível para o mundo. Com esse token, consigo fazer deploy automático sempre que uma tarefa for concluída, sem você precisar apertar um único botão.

1 Acesse vercel.com → faça login → clique na sua foto → Account Settings.
2 No menu lateral, clique em Tokens → Create Token. Escopo: Full Account.

Documentação Viva (Context7)

✓ Sem token necessário

O Context7 é como ter a documentação oficial atualizada de qualquer biblioteca sempre à mão — em tempo real, sem precisar googlar. Sem ele, os agentes ficam com conhecimento defasado e cometem erros desnecessários com versões antigas de frameworks.

📦 Config do MCP (para ~/.claude/settings.json)
"context7": {
  "command": "npx",
  "args": ["-y", "@upstash/context7-mcp@latest"]
}
1 No Claude Code, abra as configurações de MCP (Settings → MCP Servers).
2 Adicione o bloco acima. O Claude vai baixar e iniciar o servidor automaticamente.
3 Confirme abaixo quando terminar — ou pule e faça depois.

Olhos no Browser (Playwright)

✓ Sem token necessário

O Playwright MCP dá à Ravena (QA) a capacidade de abrir um browser real, clicar em botões, preencher formulários e tirar screenshots — exatamente como um usuário faria. Sem isso, os testes são apenas palavras. Com isso, são provas.

📦 Config do MCP (para ~/.claude/settings.json)
"playwright": {
  "command": "npx",
  "args": ["-y", "@executeautomation/playwright-mcp-server"]
}
1 Adicione o bloco acima em Settings → MCP Servers no Claude Code.
2 O npx vai instalar o servidor Playwright automaticamente na primeira execução.

Raio-X do Front (Chrome DevTools)

✓ Sem token necessário

O Chrome DevTools MCP conecta os agentes diretamente ao seu browser — eles conseguem ler o console, inspecionar erros de rede, tirar screenshots e até executar JavaScript na página. É como ter um DevTools aberto, mas controlado pela IA. Essencial para debug de frontend.

📦 Config do MCP (para ~/.claude/settings.json)
"chrome-devtools": {
  "command": "npx",
  "args": ["-y", "@modelcontextprotocol/server-puppeteer"]
}
1 Adicione o bloco acima em Settings → MCP Servers no Claude Code.
2 Tenha o Google Chrome instalado na sua máquina (o servidor usa o Chrome do sistema).

Arsenal de Segurança (CLIs)

✓ Sem token necessário

O Kerberos usa 3 ferramentas de linha de comando para fazer auditorias reais — não são simulações, são as mesmas ferramentas que hackers éticos usam em produção. Cada uma tem um papel específico na proteção do seu projeto.

🔍 TruffleHog — Farejador de secrets. Vasculha todo o código em busca de tokens, senhas e chaves expostas acidentalmente.
pip install trufflehog
🛡️ Semgrep — Scanner de vulnerabilidades no código (SQL Injection, XSS, etc.) antes do deploy.
pip install semgrep
⚡ Nuclei — Testa vulnerabilidades reais na URL do projeto com templates atualizados da comunidade.
go install github.com/projectdiscovery/nuclei/v3/cmd/nuclei@latest
