## 📋 PROTOCOLO COMPLETO DE QA (O QUE TESTAR)

### 🗺️ FASE 1 — MAPEAMENTO DE ROTAS

Antes de testar, liste todas as rotas do projeto. Procure em:
- `app/` ou `pages/` (Next.js)
- `src/routes/` ou `router/` (React/Vue)
- Qualquer arquivo de configuração de rotas

Para CADA rota encontrada:
1. `browser_navigate(rota)` — abrir
2. `browser_take_screenshot()` — documentar
3. `browser_console_messages()` — checar erros
4. Verificar se carregou corretamente (não é 404, não é tela branca)

### 🖱️ FASE 2 — TESTE DE INTERATIVIDADE

Para CADA elemento interativo encontrado via `browser_snapshot()`:

**Botões:**
- `browser_click(ref)` em TODOS os botões
- Verificar se ação ocorreu (navegação, modal, feedback)
- Screenshot antes e depois

**Formulários:**
- `browser_fill_form()` com dados válidos → verificar sucesso
- `browser_fill_form()` com dados inválidos → verificar mensagem de erro
- Testar validação de campos obrigatórios (enviar vazio)
- Verificar comportamento do botão submit

**Links e Navegação:**
- Clicar em todos os links
- Verificar se destino é correto
- Checar links externos (abrem em nova aba?)
- Verificar breadcrumbs e menus

**Modais e Dropdowns:**
- Abrir → verificar conteúdo
- Fechar (X, backdrop, Escape) → verificar fechamento
- Interagir com conteúdo interno

### 🎨 FASE 3 — VERIFICAÇÃO DE CSS/TAILWIND

Use `browser_evaluate` para checar estilos reais:

```javascript
// Detectar elementos sem estilo (possível Tailwind quebrado)
const elements = document.querySelectorAll('[class*="bg-"], [class*="text-"], [class*="flex"]');
const broken = Array.from(elements).filter(el => {
  const styles = window.getComputedStyle(el);
  return styles.display === '' || styles.backgroundColor === '';
});
return broken.map(el => ({ tag: el.tagName, classes: el.className }));
```

```javascript
// Verificar se fontes customizadas carregaram
const fontFaces = [...document.fonts].map(f => ({ family: f.family, status: f.status }));
return fontFaces;
```

```javascript
// Checar elementos com overflow oculto (conteúdo cortado)
const all = document.querySelectorAll('*');
const overflowing = Array.from(all).filter(el => {
  return el.scrollWidth > el.clientWidth || el.scrollHeight > el.clientHeight;
}).slice(0, 10);
return overflowing.map(el => ({ tag: el.tagName, id: el.id, class: el.className.substring(0, 50) }));
```

**O que verificar visualmente via screenshot:**
- Textos ilegíveis (baixo contraste)
- Elementos sobrepostos
- Imagens quebradas (alt text visível)
- Ícones não carregados
- Animações travadas
- Hover states funcionando

Para cada viewport:
1. `browser_navigate(url)` — recarregar

### 🚦 FASE 5 — ERROS DE CONSOLE E REDE

```
browser_console_messages()    → capturar todos os logs
browser_network_requests()    → capturar todas as requisições
```

**Erros críticos (REPROVAÇÃO AUTOMÁTICA):**
- `TypeError`, `ReferenceError`, `SyntaxError` no console
- Requisições com status 500, 503 (erro servidor)
- Requisições com status 401, 403 em rotas públicas
- CORS errors

**Alertas (avisos):**
- Status 404 em assets (imagens, fontes, scripts)
- Warnings de deprecação
- Requests lentos (>3s)

### ♿ FASE 6 — ACESSIBILIDADE BÁSICA

Use `browser_evaluate` para checar via axe-core:

```javascript
// Verificações manuais sem lib externa
const issues = [];

// Imagens sem alt
document.querySelectorAll('img:not([alt])').forEach(img => {
  issues.push({ type: 'img-sem-alt', src: img.src });
});

// Inputs sem label
document.querySelectorAll('input:not([aria-label]):not([id])').forEach(input => {
  issues.push({ type: 'input-sem-label', type_attr: input.type });
});

// Botões sem texto
document.querySelectorAll('button').forEach(btn => {
  if (!btn.textContent.trim() && !btn.getAttribute('aria-label')) {
    issues.push({ type: 'botao-sem-texto', classes: btn.className });
  }
});

// Links sem texto
document.querySelectorAll('a').forEach(link => {
  if (!link.textContent.trim() && !link.getAttribute('aria-label')) {
    issues.push({ type: 'link-sem-texto', href: link.href });
  }
});

return issues;
```

## 🧹 PROTOCOLO DE LIMPEZA (OBRIGATÓRIO AO ENCERRAR)

Após gerar o relatório final, **sempre** execute a limpeza dos arquivos temporários criados durante o QA.

### O que limpar:

```bash
# 1. Screenshots temporários gerados pelo Playwright MCP
rm -f /tmp/playwright-screenshots-* 2>/dev/null
rm -f /tmp/screenshot-*.png 2>/dev/null
rm -rf /tmp/playwright_* 2>/dev/null

# 2. Se screenshots foram salvos na pasta do projeto (verificar antes de apagar):
find . -maxdepth 2 -name "screenshot-*.png" -newer package.json -delete 2>/dev/null
find . -maxdepth 2 -name "*.screenshot.png" -delete 2>/dev/null

# 3. Fechar o browser ao finalizar
# (via mcp__plugin_playwright_playwright__browser_close)
```

### Regras da limpeza:

- ✅ Apagar screenshots temporários **após** o relatório estar completo
- ✅ Fechar o browser com `browser_close` ao final de cada sessão de QA
- ✅ Se um screenshot foi citado no relatório como evidência de bug crítico → **manter** com nome descritivo (ex: `qa-bug-login-modal.png`)
- ❌ Nunca apagar screenshots antes de gerar o relatório
- ❌ Nunca apagar arquivos do projeto — apenas temporários do QA

### Fala padrão ao encerrar:

```

[N screenshot(s) de evidência de bug foram mantidos em: qa-*.png]
```
